# energypotion-site — 커뮤니티에 걸 광고 링크가 도착하는 곳

| | |
|---|---|
| `index.html` | **광고가 도착하는 곳.** 게임 여섯 개가 각각 한 블록씩, 블록마다 자기 스토어 버튼을 답니다 |
| `<게임>.html` | 게임 한 개짜리 랜딩 여섯 장. 커뮤니티 글이 **한 게임 얘기일 때**만 이쪽으로 |
| `assets/data.js` | 게임별 이름·한 줄 소개·포인트·상세 표·스토어 링크가 사는 유일한 곳. **배열 순서가 페이지 순서입니다** |
| `tools/make_shots.py` | 스크린샷·아이콘·`assets/shots.js` 를 스토어 기준으로 다시 만듭니다 |
| `tools/make_og.py` | 링크 카드 일곱 장을 다시 만듭니다 |
| `app-ads.txt` | AdMob 이 가져가는 파일. **지우지 말 것** — 아래 참고 |

## 배경은 중립이고, 색은 게임의 것입니다

바탕이 Echo Step 의 하늘색이었습니다 — 이 페이지가 그 게임의 랜딩으로 시작했기
때문입니다. 카탈로그가 된 지금 그건 **한 게임의 페이지에 다섯이 얹혀 있는**
모양이고, 청록이 Catch Catch 의 노랑과 Space Fighter 의 주황과 싸웁니다.

Gemini 와 ChatGPT 에 같은 질문을 각각 던졌고 둘 다 중립 다크를 골랐습니다.
근거도 같습니다: 스튜디오 카탈로그는 배경의 존재감을 지워야 각 게임의 고유색이
독립적인 모듈로 선다는 것 (Supercell·Devolver·Klei 등이 그렇게 합니다).

그래서 `--bg: #111417` 의 중립 다크이고, **`--accent` 의 기본값은 색이 아니라
회색**입니다. 진짜 색은 `data.js` 의 게임별 `accent` 가 블록과 요약 행에
인라인으로 넣습니다. 크롬이 무채색으로 남는 것이 여섯 개의 강조색이 한 장에서
싸우지 않는 이유입니다. **크롬에 색을 되돌리려면 그 게임 하나를 고르는 셈이
되므로, 하지 마세요.**

## 언제 공유를 시작하는가

**Catch Catch 가 스토어에 올라간 뒤입니다.** 그때까지 이 링크는 아무 데도 걸지
않습니다. 승인되면 `data.js` 의 Catch Catch `ios` 에
`https://apps.apple.com/app/id6804225701` 을 넣고, Play 에 올라가면 `android` 도
채웁니다. Play 는 아직 올리지 않았으므로 그전까지 안드로이드 버튼은 `출시 준비 중`
입니다.

이유는 페이지가 스스로 드러냅니다. 링크가 없는 블록의 버튼은 `준비 중` 으로
그려지는데, 그건 정직하긴 해도 **광고가 도착할 자리는 아닙니다** — 클릭당 돈을
낸 사람을 누를 수 없는 버튼 앞에 세우는 셈이니까요. 그래서 공개 조건은
"페이지가 완성되면" 이 아니라 **"큰 블록 여섯 개의 버튼이 전부 살아 있으면"**
입니다.

지금 큰 블록은 **Catch Catch · Echo Step · Prism Dash · Skydiver ·
Invader Z · Space Fighter** 여섯 개입니다. 이 구성과 순서는 `data.js` 배열이
전부입니다.

## 한 장에 여섯 개를 담을 때의 규칙

여섯 개를 늘어놓는 것 자체는 괜찮습니다. 안 되는 것은 **여섯 개를 늘어놓고
버튼은 맨 아래 하나만 두는 것**입니다. 네 번째 게임까지 스크롤한 사람은 위로
돌아가지 않습니다. 그래서 블록마다 스토어 버튼이 붙어 있고, 블록 하나가
그 자체로 작은 랜딩 페이지 한 장입니다 — 화면, 한 문장, 버튼 둘.

세 가지가 여기서 따라 나옵니다.

* **블록은 세로로 쌓입니다** — 스크린샷 두 장이 위, 이름과 한 문장과 버튼이
  그 아래. 좌우 2단은 웹사이트의 소개 행처럼 읽히고, 세로로 쌓은 것은 스토어
  항목처럼 읽힙니다. 커뮤니티 글에서 넘어온 사람이 기대하는 쪽은 후자입니다.
  대가는 페이지 길이이고, 그건 감수합니다 — 블록 하나하나가 훑고 지나갈 행이
  아니라 멈추는 자리여야 하니까요.
* **순서가 곧 편집입니다.** 광고를 보고 온 사람 대부분은 첫 블록, 잘해야 둘째
  블록까지만 봅니다. `data.js` 의 배열 순서가 페이지 순서이고, 제일 센 게임이
  맨 앞입니다. 최신순도 아니고 만든 순도 아닙니다.
* **여섯이 한계입니다.** `feature: true` 인 것만 큰 블록으로 나갑니다. 그 이상은
  페이지가 읽히지 않고 넘겨집니다.
* **히어로 밑 요약 목록은 2열입니다.** 한 줄로 흘리면 여섯 개가 5 + 1 로
  깨져서 목록이 아니라 남은 조각처럼 보입니다. 2열 3행이면 여섯이든 여덟이든
  모양이 유지됩니다 (560 아래에서는 1열).

  **여기에는 장르만 적고, 블록이 할 말을 미리 하지 않습니다.** 바로 아래에
  있는 문장을 다시 쓰는 요약은 요약이 아닙니다. 실제로 조사한 사이트들 중
  같은 목록을 위아래로 두 번 놓은 곳은 없었고 (ustwo·Noodlecake 은 세로 블록만,
  Tinybop·반지하게임즈는 압축 그리드만), Halfbrick 만이 둘을 섞는데 그쪽은
  **위가 소수의 대표작, 아래가 이름만 있는 전체 목록**입니다. 여기서는 순서가
  뒤집혀 있으므로 — 위가 전체 요약, 아래가 상세 — 위쪽에서 반복을 덜어내는
  것으로 균형을 맞췄습니다.

  `#slug` 앵커는 그대로라 `?c=ruliweb#skydiver` 같은 링크는 그 블록으로
  바로 떨어집니다.

## 링크를 두 종류로 쓰는 법

| 커뮤니티 글이 | 링크 |
|---|---|
| "제가 만든 게임들입니다" | `/` 또는 `/?c=<커뮤니티>` |
| "이 게임 하나 만들었습니다" | `/echo-step.html?c=<커뮤니티>` |
| 여섯 중 하나를 가리키는 글 | `/?c=<커뮤니티>#skydiver` |

가운데 것을 남겨둔 이유는 **`og:image` 가 페이지당 하나**이기 때문입니다.
링크를 붙였을 때 피드에 뜨는 카드는 한 장뿐이라, 한 게임 얘기를 하는 글에
목록 페이지를 걸면 카드에는 다른 게임이 뜹니다.

## 게임을 하나 더 추가하기

1. `assets/data.js` 의 `APPS` 에 항목을 채웁니다 — `tag` / `line` / `points`
   세 줄 / `facts` / 스토어 링크. `feature: true` 면 첫 페이지의 큰 블록으로
   나갑니다.
2. `echo-step.html` 을 `<slug>.html` 로 복사합니다.
3. 바꿀 것은 **다섯 군데뿐**입니다: `<title>`, `<meta name=description>`,
   `og:title` / `og:description` / `og:image`, 그리고 `<body data-app="...">`.
   히어로·포인트·상세 표는 전부 `data.js` 에서 그려집니다.

**상세 표에 가격과 광고 길이 줄은 직접 넣지 마세요.** 여섯 개 전부에 해당하는
두 줄이라 `site.js` 가 각 표의 처음과 끝에 붙입니다 — 게임마다 한 벌씩 적어두면
그중 하나가 지난달 답을 계속 말하고 있게 됩니다. `facts` 가 비어 있으면 그
게임의 상세 표는 아예 그려지지 않습니다(빈 표에 제목만 남지 않도록).

## 위쪽이 먼저 뜹니다 — 이 순서를 깨지 마세요

광고로 들어온 사람은 첫 화면에서 판단합니다. 그래서 받는 순서를 정해 두었습니다.

1. **HTML 과 CSS 만으로 첫 화면이 그려집니다.** 헤드라인·보조문장은 `index.html`
   에 세 언어로 들어 있고, `<head>` 의 인라인 스크립트가 고른 언어만 CSS 가
   보여 줍니다. 문구를 고칠 곳은 `data.js` 가 아니라 `index.html` 입니다.
2. **대표 이미지가 그다음입니다.** 같은 인라인 스크립트가 `preload` 를 겁니다.
3. **아래쪽 블록의 글자는 `defer` 스크립트가 채웁니다.** 첫 화면을 막지 않습니다.
4. **아래쪽 이미지는 대표 이미지가 도착한 뒤에야 요청합니다**(`wakeImages`, 최대
   2.5초 대기). 그 뒤에도 `loading="lazy"` 라 스크롤이 가까워질 때만 받습니다.
5. **`shots.js` 의 크기로 자리를 미리 잡아 둡니다.** 이미지가 늦게 와도 글자가
   밀리지 않습니다. 그래서 스크린샷은 `make_shots.py` 로만 넣습니다.

폰트는 렌더링을 막지 않게 걸어 두었습니다. 외부 호스트가 느려도 첫 화면은
기다리지 않습니다.

## 스크린샷과 스토어 정보

* **스크린샷을 바꾸려면** `/usr/bin/python3 tools/make_shots.py` 후
  `/usr/bin/python3 tools/make_og.py`. Catch Catch 는 ProjectH 의
  `store/screenshots` 에서, 나머지는 Apple 공개 조회 API 에서 언어별로 받습니다.
* **Catch Catch 첫 이미지는 플레이 화면**(`01_game_landscape`)입니다.
* **게임 소개는 스토어 설명과 코드에서 옮깁니다.** 기억으로 쓴 문장 세 개가 거짓
  이었습니다: Catch Catch 에 시계가 없다, Invader Z 는 편대 슈팅이다, Space Fighter
  는 누르는 동안 쏜다.
* **히어로의 주장은 여섯 게임 전부에 참이어야 합니다.** "인앱 결제 0원" 과 "보상형뿐,
  배너도 거절할 수 없는 광고도 없음". "직접 누를 때만 나온다" 라고 쓰면 거짓입니다 —
  Space Fighter 의 스테이지 클리어 광고는 5초 뒤 자동 재생되고, 그동안 NO THANKS 로
  거절합니다. 광고 방식이 바뀌면 이 문장부터 고칩니다.
* **영상**: 게임 페이지 대표 이미지 자리는 8초 무음 영상으로 바꿀 수 있습니다(2 MB 이하).

## `app-ads.txt` 는 페이지가 아니고, 이 저장소에서 지우면 안 됩니다

`energypotion-legal` 의 것과 **같은 한 줄**입니다. 스토어 listing 의 마케팅
URL 을 언젠가 이 사이트로 옮긴다면, AdMob 은 그 호스트에서 이 파일을 찾습니다.
없으면 광고는 당분간 그대로 나오고 **수익만 조용히 줄어듭니다.**
옮기기 전에는 `energypotion-legal` 쪽 `CLAUDE.md` 를 먼저 읽을 것.

확인은 상태 코드가 아니라 본문으로:

    curl -s https://<호스트>/app-ads.txt

## 배포 — GitHub Pages

무료입니다. public 저장소면 커스텀 도메인과 HTTPS 까지 공짜고, 한도는
저장소 1 GB · 월 100 GB 전송으로 광고 트래픽에는 넉넉합니다.

주의: 이 프로젝트들의 `origin` 은 NAS(`192.168.50.250`)이고 GitHub 이 아닙니다.
이 사이트만은 GitHub 의 **public** 저장소여야 Pages 가 붙습니다.

```bash
cd /Volumes/ROG-ESD-S1C/Projects/energypotion-site
git init && git add -A && git commit -m "Studio site skeleton"
git branch -M main
git remote add origin git@github.com:<계정>/energypotion-site.git
git push -u origin main
# GitHub → Settings → Pages → Source: main / (root)
```

`.nojekyll` 이 이미 있습니다 — Jekyll 이 `assets/` 를 건드리지 않게 합니다.

대안 두 가지, 고를 때 근거만:

* **Cloudflare Pages** — 전송량 무제한. 커뮤니티 여러 곳에 동시에 걸어 트래픽이
  튀는 것이 걱정된다면 이쪽이 가장 안전합니다.
* **Firebase Hosting** — 이미 두 개(`energypotion-legal`, `invaderz-site`)를
  이렇게 서비스하고 있으니 손에 익습니다. 다만 Spark 무료 한도는 **하루 360 MB
  전송**이라, 영상을 얹은 랜딩 페이지에 광고를 걸면 하루에 넘길 수 있습니다.

## 어디서 온 클릭인지 세기

광고 링크 끝에 `?c=` 를 붙이면 (`.../echo-step.html?c=ruliweb`)
스토어 버튼이 그 값을 그대로 스토어로 넘깁니다 — Play 는 `referrer`,
App Store 는 캠페인 토큰 `ct`. 페이지 자체에는 추적기가 없습니다.
쿠키 배너가 필요 없는 이유이기도 하고, 앱의 개인정보처리방침이 내세우는
"프로필을 만들지 않는다"와 사이트가 어긋나지 않게 하는 유일한 방법입니다.
숫자가 더 필요해지면 쿠키 없는 것(Cloudflare Web Analytics, Plausible)으로.

App Store 쪽 `ct` 가 App Analytics 에 보이려면 `pt`(provider id)가 한 번
들어가야 합니다. `site.js` 의 `storeUrl()` 에 자리를 비워 두었습니다.

## 미리보기

파일을 그냥 열면 됩니다(빌드 없음). 한 파일로 합쳐 보려면:

```bash
python3 tools/inline.py echo-step.html /tmp/preview.html
```

언어는 `?lang=ko` / `?lang=ja` / `?lang=en` 로 강제할 수 있습니다.
아무것도 주지 않으면 브라우저 설정을 따르고, 고른 값은 저장됩니다 —
`ECHO_LANG > es.lang > 단말` 과 같은 순서입니다.
